VIGIL now has a time-aligned fusion coordinator for calibrated spatial observations, 2.4 GHz Wi-Fi CSI motion evidence, and calibrated infrared floor maps. CSI PIPELINE // END-TO-END EVIDENCE Aligned CSI samples now have a defined software path: feature extraction → temporal motion filtering → timestamped SQL telemetry. The pipeline validates ordered timestamps and records sensor identity, channel, packet metadata, signal level, and filtered evidence. Motion evidence is not a location estimate; object position still requires calibrated ranging or other spatial observations and the existing tracker. SQL TELEMETRY // SAFE INGESTION VIGIL now has a local SQLite telemetry event store for router/CSI diagnostics. It records timestamps, sensor IDs, protocol metadata, packet lengths, channel, optional signal level, and filtered motion evidence — not raw packet payloads. Every database value is bound through parameterized SQL. This is deliberately not SQL injection or packet injection into a router: sensing remains passive/authorized, and telemetry storage is separated from router control. Hardware adapters and live router integration remain unconnected until a supported, authorized interface is configured. TEMPORAL STABILITY // NEW MILESTONE

STRUCTURED SENSOR EVENT MODEL // NEW SOFTWARE MILESTONE
VIGIL now defines a validated, normalized event record for dashboard and API handoff: event ID, sensor ID, monotonic-domain timestamp, modality, event kind, accepted/context/rejected/warning status, explicit reason, sequence, optional signal/confidence/uncertainty, calibration state, and blueprint model/revision/frame provenance. Validation rejects invalid timestamps, confidence outside 0–1, negative uncertainty, malformed IDs, and duplicate ledger event IDs. The in-memory ledger provides newest-first snapshots with age and count limits. The CSI/telemetry adapter maps existing pipeline outputs into this contract, preserving signal and evidence scores separately from confidence. OPERATOR DISPLAY ARCHITECTURE // REMOTE BROWSER

DECISION: The intended operator screen is a remote screen accessed through a browser. The browser-based Control Room remains the development/documentation surface; the eventual operator interface must display state from the actual Coreless/VIGIL runtime.

1 // SYSTEM BOUNDARIES

  • Runtime is authoritative: Coreless/VIGIL owns sensor events, timestamps, track state, fusion, uncertainty, provenance, health, and authorization.
  • Browser is a client: it renders server-provided state and submits operator intent; it cannot grant permissions or become the source of truth.
  • No second AI authority: VIGIL continues to use the existing Coreless AI registry/controller and Qwen3 boundary.
  • Settings distinction: the current website settings are browser-side presentation preferences, not controls of physical sensors or runtime hardware.

2 // CONNECTION AND SAFETY REQUIREMENTS

  • HTTPS plus authenticated sessions; server-side authorization for every runtime-changing command. No secrets in client code or URLs.
  • Separate read-only telemetry from commands. Validate command schema, capability, scope, freshness, and authorization inside Coreless.
  • Prefer WebSocket or Server-Sent Events for live updates, with bounded polling as fallback; include sequence/cursor and source-time metadata for gap and staleness detection.
  • Show connected, stale, disconnected, and degraded states. Endpoint reachability does not prove physical sensor connectivity or valid measurements.
  • Preserve modality, units, calibration, uncertainty, and provenance. Wi-Fi CSI, calibrated ranging, infrared, and acoustic sonar remain distinct evidence types.
  • Support responsive browser layouts, keyboard/accessibility, reduced motion, and reconnect without silently losing operator context.
